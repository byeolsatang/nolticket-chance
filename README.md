# キャンセル拾いチャンスメーター

NOL Ticket のキャンセル料フェーズをもとに、戻り席が出やすそうなタイミングを可視化するための個人用観測ツールです。

このツールは、チケットを自動取得するものではありません。
キャンセル料の上がり方やキャンセル締切をもとに、どのタイミングを注視するとよさそうかを整理するための補助ツールです。

## このツールでできること

入力された以下の情報をもとに、現在のキャンセル料フェーズを判定します。

- 公演日
- チェック日
- チェック時刻

判定結果として、以下を表示します。

- 現在のフェーズ
- 公演何日前か
- キャンセル締切
- 戻り席チャンス
- 直前放出ブースト
- 次フェーズへの切り替えタイミング
- キャンセルフェーズのタイムライン

---

## 基本ロジック

キャンセル料フェーズは、以下の考え方で判定しています。

```text
公演日 - チェック日 = 公演何日前か
```

この「公演何日前か」をもとに、現在がどのキャンセル料フェーズにいるかを判定します。

---

## フェーズ判定

現在のロジックでは、以下のルールで判定しています。

| 公演日までの日数 | フェーズ | 表示 |
|---:|---|---|
| 36日前以前 | 無料期間 | 無料キャンセル |
| 35日前〜10日前 | 均一フェーズ | 4,000won/枚 |
| 9日前〜7日前 | 10%フェーズ | チケット価格の10% |
| 6日前〜3日前 | 20%フェーズ | チケット価格の20% |
| 2日前〜前日17:00まで | 30%フェーズ | チケット価格の30% |
| 公演前日17:00以降 | 終了 | キャンセル受付終了 |

キャンセル締切は、現時点では以下の前提で固定しています。

```text
公演前日 17:00
```

---

## チャンス度について

各フェーズには、仮の「チャンス度」を設定しています。

| フェーズ | チャンス度 |
|---|---:|
| 無料期間 | 5% |
| 均一フェーズ | 25% |
| 10%フェーズ | 50% |
| 20%フェーズ | 75% |
| 30%フェーズ | 95% |
| 終了 | 0% |

これは公式の数値ではありません。

キャンセル料が上がるにつれて、損失を避けたい保有者がチケットを手放しやすくなる可能性がある、という仮説にもとづいた目安です。

---

## 直前放出ブーストについて

このツールでは、通常のフェーズスコアに加えて、次のフェーズ切り替えやキャンセル締切が近づいたときに「直前放出ブースト」を加算しています。

考え方は以下です。

```text
手数料アップが近づく
↓
損切り判断が起こりやすくなる
↓
戻り席が出やすくなる可能性がある
```

このブーストは、取れる確率を保証するものではありません。
あくまで、注視すべきタイミングを見つけるための補助指標です。

## 合言葉ののれんについて

このアプリとロジック説明ページには、簡易的な「合言葉ののれん」を設置しています。

これは強いセキュリティを目的としたものではありません。
URLを知っているだけで誰でもそのまま使える状態を避けるための、軽い入口です。

このようなロジックは、自分で観察し、試行錯誤しながら対応している方にとって、大切なノウハウでもあります。
そのため、広く無制限に公開するのではなく、発信を見てくださっている方へ向けた形にしています。

私はUX/UIデザイナーとして、単に情報を出すだけでなく、使う人・見る人・自力で研究している人それぞれの体験にも配慮したいと考えています。

そのため、完全に閉じるのではなく、かといってURLだけで素通りできる状態にもせず、ささやかな「のれん」として合言葉入力を設けています。

## 合言葉の運用方針

合言葉は `gate.js` で管理しています。

```js
var GATE_PASSPHRASE = '拾い日和';
```

合言葉は定期的に変更し、Instagram ストーリーズでお知らせします。

Instagram:  
https://www.instagram.com/byeolsatang__/

---

## 一度入室した人の扱い

このアプリでは、合言葉を一度入力して入室すると、同じブラウザでは再入力なしで入れるようにしています。

これは、毎回合言葉を入力する負担を減らすためです。

通過状態は `localStorage` に保存しています。

```js
var GATE_STORAGE_KEY = 'nolticketChanceGatePassedV1';
```

---

## 合言葉を変えたときの運用

合言葉だけを変更した場合、すでに入室済みの人は引き続き入れます。

```js
var GATE_PASSPHRASE = '席こい';
```

これは、新しくアクセスする人向けに合言葉を更新する運用です。

---

## 全員に再入力してもらいたい場合

公演が変わったときや、配布範囲を切り替えたいときは、合言葉だけでなく `GATE_STORAGE_KEY` も変更します。

例：

```js
var GATE_PASSPHRASE = '拾い日和';
var GATE_STORAGE_KEY = 'nolticketChanceGatePassed_202606_KINTEX';
```

次の公演では、以下のように変更します。

```js
var GATE_PASSPHRASE = '席こい';
var GATE_STORAGE_KEY = 'nolticketChanceGatePassed_202609_LA';
```

`GATE_STORAGE_KEY` を変えることで、以前に入室済みだった人も再度合言葉入力が必要になります。

## おすすめの運用

通常は以下の運用を想定しています。

### 通常更新

```text
GATE_PASSPHRASE のみ変更
```

- 新規アクセス向けに合言葉を更新
- すでに入室済みの人はそのまま使える
- ユーザー体験を邪魔しにくい

### 公演切り替え時

```text
GATE_PASSPHRASE と GATE_STORAGE_KEY の両方を変更
```

- 公演単位で入口を切り替える
- 全員に再入力してもらえる
- ストーリーズで「今回の合言葉」を案内できる

この運用が、限定感と使いやすさのバランスがよいと考えています。

## 注意点

このツールは、NOL Ticket公式の仕様を保証するものではありません。

表示されているキャンセル料テーブルや、観測にもとづく仮説をもとにした個人用の判断補助ツールです。

また、キャンセル席が実際に出るかどうかは、チケット保有者の行動、販売状況、システム反映タイミングなどに左右されます。

このツールのスコアは「取れる確率」ではなく、注視すべきタイミングの目安として扱います。
